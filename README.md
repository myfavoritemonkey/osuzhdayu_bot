# Бот «Осуждаю»

Telegram-бот отвечает на сообщения с «осуждаю» короткой остроумной репликой,
сгенерированной через DeepSeek API. Дополнительно можно включить осторожный
режим диалога с обращениями к боту.

## Установка

Нужен Python 3.10 или новее.

```bash
cd /home/pc/my/projects/osuzhdayu_bot
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
```

Заполните `config.cfg`: токен Telegram-бота и ключ DeepSeek. Бот отвечает любому
пользователю, чьё сообщение содержит триггер. Файл уже добавлен в `.gitignore`,
поэтому секреты не должны попасть в репозиторий.

Чтобы отвечать на пересланные из группы сообщения, включите в секции
`[telegram]`:

```ini
relay_forwarded_messages = true
relay_chat_id = -1001234567890
```

`relay_chat_id` — ID общего чата. Его можно узнать командой `/id`, отправленной
в этом чате. После этого перешлите сообщение из группы боту в личные сообщения.
Бот сопоставит пересланный текст с кэшем сообщений группы и отправит только
сгенерированный ответ через reply на найденное оригинальное сообщение. Если
оригинал уже не попал в кэш, бот ничего не публикует. Поэтому сначала запустите
бота, убедитесь, что Privacy Mode отключён, отправьте исходное сообщение в
группу, и только затем пересылайте его боту в ЛС.

## Настройка Telegram-группы

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. В @BotFather выполните `/setprivacy` → выберите бота → `Disable`, либо
   добавьте бота администратором. Это необходимо, чтобы бот видел обычные
   сообщения группы, а не только команды/ответы ему.
3. Добавьте бота в нужную беседу.
4. Напишите в группе сообщение с «осуждаю» для проверки.

## Запуск

```bash
python bot.py
```

Бот использует long polling, поэтому отдельный сервер и webhook не нужны.
Срабатывание проверяется локально по словам из `trigger_words`; DeepSeek
вызывается только после совпадения. Бот игнорирует сообщения от других ботов,
чтобы не создавать цепочки ответов.

## Важные настройки

- `trigger_words` — список слов/фраз через запятую.
- `respond_to_direct_messages` — `true` включает обработку reply на сообщения
  бота, сообщений с его `@username` и обращений со словами из
  `bot_reference_words`; `false` оставляет только триггеры.
- `bot_reference_words` — формы слова «бот», через запятую. Их можно расширить
  под привычные варианты или опечатки в вашей беседе.
- `context_messages_after_reply` — сколько следующих сообщений после ответа
  бота анализировать по контексту; по умолчанию `3`.
- `context_reset_seconds` — время жизни контекста после ответа бота; по умолчанию
  `60` секунд. После истечения контекст полностью удаляется.
- `cooldown_seconds` — пауза между ответами в одном чате.
- `system_prompt` — стиль парировок.
- `model` — модель DeepSeek; при необходимости замените на доступную вашему
  аккаунту модель.
- `relay_forwarded_messages` — обрабатывать только пересланные сообщения из ЛС
  и публиковать ответ в общем чате.
- `relay_chat_id` — ID чата, куда отправлять ответ на пересылку.

Если DeepSeek временно недоступен, бот запишет ошибку в журнал и не отправит
сообщение-заглушку в чат.

Если Telegram уже не может найти исходное сообщение для reply (например, его
удалили), бот автоматически отправит сгенерированный ответ обычным сообщением
в тот же чат.

В режиме `respond_to_direct_messages = true` для обращений без слова-триггера
DeepSeek сначала возвращает решение `should_reply`. При сомнении бот выбирает
`false` и ничего не отправляет. Если сообщение содержит «осуждаю», ответ
генерируется напрямую без дополнительного отказа.

После каждого ответа бота открывается контекстное окно на указанное число
сообщений. В эти сообщения передаётся предыдущий ответ бота и уже проверенные
реплики; после исчерпания окна бот снова ждёт явного обращения, упоминания или
триггерного слова. Через `context_reset_seconds` контекст сбрасывается даже
если окно ещё не исчерпано, и следующий запрос получает исходный системный
промпт без старых сообщений.
